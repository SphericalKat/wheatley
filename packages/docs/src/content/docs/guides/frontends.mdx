You do not need to stay in your terminal to use Wheatley. You can connect any assistant to **Telegram**, **Slack**, or **Discord** — and even link multiple chat apps to the same assistant.

For safety, every chat connection requires an explicit `allowedChatIds` allowlist so strangers cannot message your assistant.

## Connect a chat platform

<Tabs syncKey="frontend">
  <TabItem label="Telegram">
    Telegram works out of the box with long polling — you do not need a public URL or open firewall ports.

    <Steps>
      1. **Create a bot with BotFather**

         Open Telegram, message `@BotFather`, run `/newbot`, and copy the bot token it gives you.

      2. **Find your chat ID**

         Send any message to your new bot, or message a helper bot such as `@userinfobot` to get your numeric Telegram user or group chat ID.

      3. **Save the bot token in `secrets.yaml`**

         ```yaml
         TELEGRAM_BOT_TOKEN: 123456789:AA...
         ```

      4. **Add the Telegram binding to `config.yaml`**

         ```yaml
         agents:
           default:
             frontends:
               - id: telegram-main
                 type: telegram
                 config:
                   botToken:
                     secret: TELEGRAM_BOT_TOKEN
                   allowedChatIds:
                     - 123456789
                   mode: polling
                   groupActivation: mention
                   streaming: draft
         ```

      5. **Restart your assistant** and send a message to your bot on Telegram.
    </Steps>

    ### Telegram options

    | Option | Required | Default | What it controls |
    | --- | --- | --- | --- |
    | `botToken` | Yes | — | `{ secret: "<name>" }` reference to your BotFather token |
    | `allowedChatIds` | Yes | — | User, group, or supergroup IDs (or `<chat_id>:topic:<thread_id>` for forum topics) |
    | `mode` | No | `polling` | `polling` (works behind NAT/firewalls) or `webhook` (requires a public HTTPS URL) |
    | `webhookUrl` | If `webhook` | — | Public HTTPS URL forwarded to `/frontends/<agent>/<binding-id>/updates` |
    | `groupActivation` | No | `mention` | `mention` (reply only when mentioned or replied to in groups) or `always` |
    | `streaming` | No | `draft` | `draft` (streams live edits) or `typing` (shows typing indicator until done) |
    | `draftIntervalMs` | No | `1200` | Minimum milliseconds between streamed message edits (minimum `500`) |

  </TabItem>

  <TabItem label="Slack">
    Slack uses **Socket Mode** by default, so Wheatley connects outbound to Slack without needing a public webhook URL.

    <Steps>
      1. **Create a Slack App**

         Go to [api.slack.com/apps](https://api.slack.com/apps) and create a new app for your workspace.

      2. **Enable Socket Mode and create an app-level token**

         Under **Socket Mode**, turn it on and generate an app-level token (`xapp-...`) with the `connections:write` scope.

      3. **Add Bot Token Scopes and Event Subscriptions**

         Under **OAuth & Permissions**, add these bot scopes:
         `channels:history`, `chat:write`, `commands`, `files:read`, `files:write`, `groups:history`, `im:history`, `mpim:history`, `reactions:write`, and `users:read`.

         Under **Event Subscriptions**, subscribe to bot events:
         `message.channels`, `message.groups`, `message.im`, and `message.mpim`.

         Install the app to your workspace and copy the Bot User OAuth Token (`xoxb-...`).

      4. **Save both tokens in `secrets.yaml`**

         ```yaml
         SLACK_BOT_TOKEN: xoxb-...
         SLACK_APP_TOKEN: xapp-...
         ```

      5. **Add the Slack binding to `config.yaml`**

         Copy the channel or DM ID from Slack (right-click a channel -> **View channel details** -> bottom of the dialog) and add it to `allowedChatIds`:

         ```yaml
         agents:
           default:
             frontends:
               - id: slack-main
                 type: slack
                 config:
                   transport: socket
                   botToken:
                     secret: SLACK_BOT_TOKEN
                   appToken:
                     secret: SLACK_APP_TOKEN
                   allowedChatIds:
                     - C0123456789
                   channelTrigger: mention-or-reply
                   streaming: edit
         ```

      6. **Invite the bot to your channel** (`/invite @your-bot`), restart your assistant, and mention it.
    </Steps>

    ### Slack options

    | Option | Required | Default | What it controls |
    | --- | --- | --- | --- |
    | `botToken` | Yes | — | `{ secret: "<name>" }` reference to the `xoxb-` bot token |
    | `allowedChatIds` | Yes | — | Channel IDs, DM IDs, or `<channel_id>:<thread_ts>` thread keys |
    | `transport` | No | `socket` | `socket` (Socket Mode) or `webhook` (Events API via Wheatley's webhook listener) |
    | `appToken` | If `socket` | — | `{ secret: "<name>" }` reference to the `xapp-` token |
    | `signingSecret` | If `webhook` | — | `{ secret: "<name>" }` reference to your Slack signing secret |
    | `channelTrigger` | No | `mention-or-reply` | `mention-or-reply` or `all` in channels (DMs always reach the assistant) |
    | `streaming` | No | `edit` | `edit` (streams live edits) or `typing` (shows an emoji reaction while working) |
    | `editIntervalMs` | No | `1200` | Minimum milliseconds between draft edits (minimum `1000`) |
    | `typingReaction` | No | `hourglass_flowing_sand` | Emoji name (without colons) added while a reply is in progress |

  </TabItem>

  <TabItem label="Discord">
    Discord connects over the Discord Gateway — no public webhook URL is required.

    <Steps>
      1. **Create a Discord bot**

         Open the [Discord Developer Portal](https://discord.com/developers/applications), create an application, open the **Bot** tab, and copy the bot token.

      2. **Enable Message Content Intent**

         On the **Bot** tab, enable **Message Content Intent** so your bot can read messages in your allowed channels. Invite the bot to your server using the OAuth2 URL Generator (`bot` and `applications.commands` scopes).

      3. **Copy your channel or DM IDs**

         In Discord settings under **Advanced**, enable **Developer Mode**. Right-click the channel or DM you want to allow and select **Copy Channel ID**.

      4. **Save the bot token in `secrets.yaml`**

         ```yaml
         DISCORD_BOT_TOKEN: MTIz...
         ```

      5. **Add the Discord binding to `config.yaml`**

         Keep Discord snowflake IDs wrapped in quotes so YAML treats them as strings:

         ```yaml
         agents:
           default:
             frontends:
               - id: discord-main
                 type: discord
                 config:
                   tokenSecret: DISCORD_BOT_TOKEN
                   allowedChatIds:
                     - "123456789012345678"
                   guildMessages: mention_or_reply
                   streaming: edit
                   commandGuildIds:
                     - "987654321098765432"
         ```

      6. **Restart your assistant** and message your bot in Discord.
    </Steps>

    ### Discord options

    | Option | Required | Default | What it controls |
    | --- | --- | --- | --- |
    | `tokenSecret` | Yes | — | Name of the secret in `secrets.yaml` holding your Discord bot token |
    | `allowedChatIds` | Yes | — | List of allowed DM, channel, or thread IDs (as quoted strings) |
    | `guildMessages` | No | `mention_or_reply` | `mention_or_reply` or `all` in server channels (DMs always reach the assistant) |
    | `streaming` | No | `edit` | `edit` (typing indicator plus live message edits) or `typing` (typing indicator only) |
    | `editIntervalMs` | No | `1200` | Minimum milliseconds between draft edits (`250` to `60000`) |
    | `commandGuildIds` | No | `[]` | Server IDs for instant slash command registration (leave empty for global commands) |

  </TabItem>
</Tabs>

## Binding rules to keep in mind

- Each entry in `frontends` needs a unique lowercase `id` (for example `telegram-personal`). The ID `cli` is reserved for the terminal chat.
- Set `enabled: false` on any binding to pause it temporarily without deleting its config.
- Sensitive tool calls (like running shell commands or writing files) prompt you for approval right inside Telegram, Slack, or Discord.
