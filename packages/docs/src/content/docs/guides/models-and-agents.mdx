Wheatley lets you choose the AI provider and model for each assistant. You can use hosted providers or an OpenAI-compatible proxy, and run multiple isolated assistants inside one installation.

## Pick a model provider

Wheatley supports `anthropic`, `openai`, `google`, `openrouter`, `groq`, `mistral`, `xai`, and `deepseek` out of the box.

Add your API key to `~/.wheatley/secrets.yaml`, configure `~/.wheatley/config.yaml` as shown below, and restart the assistant.

<Tabs syncKey="provider">
  <TabItem label="Anthropic">
    Add `ANTHROPIC_API_KEY: sk-ant-...` to `secrets.yaml`:

    ```yaml
    version: 1

    providers:
      anthropic:
        apiKey:
          secret: ANTHROPIC_API_KEY

    agents:
      default:
        model:
          provider: anthropic
          id: claude-sonnet-5-5
    ```
  </TabItem>

  <TabItem label="OpenAI">
    Add `OPENAI_API_KEY: sk-...` to `secrets.yaml`:

    ```yaml
    version: 1

    providers:
      openai:
        apiKey:
          secret: OPENAI_API_KEY

    agents:
      default:
        model:
          provider: openai
          id: gpt-5.4-mini
    ```
  </TabItem>

  <TabItem label="Google">
    Add `GOOGLE_API_KEY: ...` to `secrets.yaml`:

    ```yaml
    version: 1

    providers:
      google:
        apiKey:
          secret: GOOGLE_API_KEY

    agents:
      default:
        model:
          provider: google
          id: gemini-2.5-pro
    ```
  </TabItem>

  <TabItem label="OpenRouter">
    Use any supported provider name (`openrouter`, `groq`, `mistral`, `xai`, or `deepseek`) with a matching model ID:

    ```yaml
    version: 1

    providers:
      openrouter:
        apiKey:
          secret: OPENROUTER_API_KEY

    agents:
      default:
        model:
          provider: openrouter
          id: anthropic/claude-sonnet-4
    ```
  </TabItem>

  <TabItem label="Custom proxy">
    To route requests through an OpenAI-compatible gateway (such as LiteLLM or a self-hosted proxy), set `baseUrl` on the `openai` provider and pick an OpenAI model ID recognized by Wheatley:

    ```yaml
    version: 1

    providers:
      openai:
        baseUrl: https://llm.example.com/v1
        apiKey:
          secret: OPENAI_API_KEY

    agents:
      default:
        model:
          provider: openai
          id: gpt-5.4-mini
    ```
  </TabItem>
</Tabs>

### Reasoning effort and concurrency limits

- **Reasoning effort**: For models that support extended thinking, set `model.thinking` to `off`, `low`, `medium`, or `high`.
- **Rate-limit protection**: If multiple assistants share one provider key, set `maxConcurrent` under that provider to cap simultaneous requests.

```yaml
providers:
  anthropic:
    apiKey:
      secret: ANTHROPIC_API_KEY
    maxConcurrent: 4

agents:
  default:
    model:
      provider: anthropic
      id: claude-sonnet-5-5
      thinking: medium
```

## Run multiple assistants

Every entry under `agents:` is completely isolated, with its own model, instructions, memory, workspace, permissions, and chat apps:

```yaml
version: 1

providers:
  anthropic:
    apiKey:
      secret: ANTHROPIC_API_KEY
  openai:
    apiKey:
      secret: OPENAI_API_KEY

agents:
  personal:
    instructions: Keep replies short, clear, and practical.
    maxConcurrentRuns: 2
    model:
      provider: anthropic
      id: claude-sonnet-5-5

  research:
    instructions: Verify facts carefully and cite primary sources.
    model:
      provider: openai
      id: gpt-5.4-mini
```

### Selecting an assistant in the CLI

If you have an assistant named `default`, `wheatley chat` and `wheatley ask` use it automatically. Otherwise, pass `--agent <name>`:

```bash
wheatley chat --agent personal
wheatley ask --agent research "Compare SQLite WAL and rollback journal modes"
```

You can also switch models temporarily inside an active CLI chat with `/model <model-id>`.
