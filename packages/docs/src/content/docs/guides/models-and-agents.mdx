Wheatley lets you pick the AI provider and model you want for each assistant. You can use hosted providers or point Wheatley at an OpenAI-compatible proxy, and you can run several independent assistants inside a single Wheatley installation.

:::tip After editing `~/.wheatley/config.yaml`, restart the assistant you changed (run `/restart` in `wheatley chat`, restart it from the dashboard, or run `wheatley service restart`). Wheatley does not restart assistants automatically on file save. :::

## Pick a model provider

Wheatley supports `anthropic`, `openai`, `google`, `openrouter`, `groq`, `mistral`, `xai`, and `deepseek` out of the box.

Put the API key in `~/.wheatley/secrets.yaml`, then reference the secret name in `~/.wheatley/config.yaml`.

<Tabs syncKey="provider">
  <TabItem label="Anthropic">
    Add `ANTHROPIC_API_KEY: sk-ant-...` to `secrets.yaml`, then update `config.yaml`:

    ```yaml
    version: 1

    providers:
      anthropic:
        apiKey:
          secret: ANTHROPIC_API_KEY

    agents:
      default:
        model:
          provider: anthropic
          id: claude-sonnet-5-5
    ```

  </TabItem>

  <TabItem label="OpenAI">
    Add `OPENAI_API_KEY: sk-...` to `secrets.yaml`, then update `config.yaml`:

    ```yaml
    version: 1

    providers:
      openai:
        apiKey:
          secret: OPENAI_API_KEY

    agents:
      default:
        model:
          provider: openai
          id: gpt-5.4-mini
    ```

  </TabItem>

  <TabItem label="Google">
    Add `GOOGLE_API_KEY: ...` to `secrets.yaml`, then update `config.yaml`:

    ```yaml
    version: 1

    providers:
      google:
        apiKey:
          secret: GOOGLE_API_KEY

    agents:
      default:
        model:
          provider: google
          id: gemini-2.5-pro
    ```

  </TabItem>

  <TabItem label="OpenRouter / Groq / others">
    Use the provider name (`openrouter`, `groq`, `mistral`, `xai`, or `deepseek`), store its key in `secrets.yaml`, and set a valid model ID for that provider:

    ```yaml
    version: 1

    providers:
      openrouter:
        apiKey:
          secret: OPENROUTER_API_KEY

    agents:
      default:
        model:
          provider: openrouter
          id: anthropic/claude-sonnet-4
    ```

  </TabItem>

  <TabItem label="OpenAI-compatible proxy">
    To route requests through an OpenAI-compatible gateway (such as LiteLLM or a self-hosted proxy), set `baseUrl` on the `openai` provider and pick an OpenAI model ID recognized by Wheatley:

    ```yaml
    version: 1

    providers:
      openai:
        baseUrl: https://llm.example.com/v1
        apiKey:
          secret: OPENAI_API_KEY

    agents:
      default:
        model:
          provider: openai
          id: gpt-5.4-mini
    ```

  </TabItem>
</Tabs>

### Adjust reasoning effort (`thinking`)

For models that support extended thinking, you can set `model.thinking` to `off`, `low`, `medium`, or `high`:

```yaml
agents:
  default:
    model:
      provider: anthropic
      id: claude-sonnet-5-5
      thinking: medium
```

### Limit concurrent provider requests

If several assistants share one API key, set `maxConcurrent` on the provider to avoid hitting rate limits:

```yaml
providers:
  anthropic:
    apiKey:
      secret: ANTHROPIC_API_KEY
    maxConcurrent: 4
```

## Run multiple assistants

Every entry under `agents:` is completely isolated: it gets its own model, system instructions, memory folder, workspace, permission rules, and chat apps.

For example, you can run a fast daily assistant alongside a deeper research assistant:

```yaml
version: 1

providers:
  anthropic:
    apiKey:
      secret: ANTHROPIC_API_KEY
  openai:
    apiKey:
      secret: OPENAI_API_KEY

agents:
  personal:
    instructions: Keep replies short, clear, and practical.
    maxConcurrentRuns: 2
    model:
      provider: anthropic
      id: claude-sonnet-5-5

  research:
    instructions: Verify facts carefully and cite primary sources.
    model:
      provider: openai
      id: gpt-5.4-mini
```

### Choosing which assistant to talk to

- If you have an assistant named `default`, `wheatley chat` and `wheatley ask` use it automatically.
- Otherwise, pass `--agent <name>`:

  ```bash
  wheatley chat --agent personal
  wheatley ask --agent research "Compare SQLite WAL and rollback journal modes"
  ```

- Inside an active CLI chat, you can also switch models for the current conversation without editing `config.yaml`:

  ```text
  /model gpt-5.4-mini
  ```
