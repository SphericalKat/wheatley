Out of the box, each Wheatley assistant can read and write files in its workspace, run shell commands, manage its memory, and schedule reminders. To add more capabilities, you can connect **MCP servers**, drop in **Markdown skills**, or write a **TypeScript plugin**.

Each assistant loads its own extensions independently. If one extension fails to start, the assistant keeps running and reports the error in `wheatley status` and the dashboard. All MCP and plugin tools require your approval by default until you allow them in [permissionPolicy](/wheatley/reference/configuration/#controlling-what-your-assistant-can-do-permissionpolicy).

## Connect an MCP server

Add Model Context Protocol servers under `agents.<name>.mcpServers` in `config.yaml`. The key you choose (for example `filesystem` or `linear`) becomes part of the tool name (`mcp:<server>:<tool>`).

<Tabs syncKey="mcp-transport">
  <TabItem label="Local command (stdio)">
    Run a local MCP server as a child process:

    ```yaml
    agents:
      default:
        mcpServers:
          filesystem:
            transport: stdio
            command: npx
            args:
              - -y
              - "@modelcontextprotocol/server-filesystem"
              - /path/to/folder
            env:
              API_TOKEN:
                secret: MY_MCP_TOKEN
    ```
  </TabItem>

  <TabItem label="Remote server (HTTP)">
    Connect to a hosted or local HTTP MCP server:

    ```yaml
    agents:
      default:
        mcpServers:
          linear:
            transport: http
            url: https://mcp.example.com/mcp
            headers:
              Authorization:
                secret: LINEAR_AUTH_HEADER
    ```
  </TabItem>
</Tabs>

Set `enabled: false` on any server entry to pause it without deleting its config.

## Add Markdown skills

A **skill** is a folder containing a `SKILL.md` file (plus any optional reference files or scripts). Wheatley exposes a catalog of available skills and lets your assistant read one on demand whenever a task matches.

Put skill folders in either location:

- **Shared across all assistants**: `~/.wheatley/skills/<skill-name>/SKILL.md`
- **Only for one assistant**: `~/.wheatley/agents/<agent-name>/skills/<skill-name>/SKILL.md`

To disable specific skills for one assistant without deleting the files:

```yaml
agents:
  default:
    skills:
      disabled:
        - draft-release-notes
```

## Write a custom plugin

To build custom tools or a custom chat frontend in TypeScript, use `@wheatley-ai/sdk`.

<Steps>

1. **Create an ESM package and install the SDK**

   ```bash
   npm install @wheatley-ai/sdk
   ```

2. **Export your plugin as the default export**

   ```ts
   import { definePlugin } from "@wheatley-ai/sdk";

   export default definePlugin({
     apiVersion: 1,
     name: "hello",
     version: "1.0.0",
     setup: () => ({
       tools: [
         {
           name: "greet",
           description: "Greets the user",
           inputSchema: { type: "object", properties: {} },
           execute: async () => ({
             content: [{ type: "text", text: "Hello" }],
           }),
         },
       ],
     }),
   });
   ```

3. **Install the plugin into Wheatley's extensions folder**

   ```bash
   npm install --prefix ~/.wheatley/extensions <plugin-package>
   ```

4. **Enable the plugin in `config.yaml` and restart your assistant**

   ```yaml
   agents:
     default:
       plugins:
         - source: <plugin-package>
   ```

</Steps>

`source` also accepts a local folder path (`./` or `../` resolves relative to `~/.wheatley`; `~/` resolves relative to your home directory). Plugin tools appear to the assistant as `<plugin>:<tool>` (for example `hello:greet`).
