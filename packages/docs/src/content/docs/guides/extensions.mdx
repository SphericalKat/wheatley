Out of the box, each Wheatley assistant can read and write files in its workspace, run shell commands (with your approval), manage its memory, and schedule reminders. When you want it to talk to external tools or follow custom workflows, you have three ways to extend it:

- **MCP servers**: Connect ready-made Model Context Protocol tools (databases, issue trackers, calendars, local utilities).
- **Skills**: Drop in plain Markdown instructions (`SKILL.md`) that your assistant loads on demand.
- **Plugins**: Write a TypeScript package with `@wheatley-ai/sdk` to add custom tools or chat frontends.

Each assistant loads its own extensions independently. If one extension fails to start, the assistant keeps running and shows the error in `wheatley status` and the web dashboard.

## Connect an MCP server

Add MCP servers under `agents.<name>.mcpServers` in `config.yaml`. The key you choose (for example `filesystem` or `linear`) becomes part of the tool name (`mcp:<server>:<tool>`).

For safety, all MCP server tools ask for your approval by default until you allow them in `permissionPolicy`.

<Tabs syncKey="mcp-transport">
  <TabItem label="Local command (stdio)">
    Run a local MCP server as a child process:

    ```yaml
    agents:
      default:
        mcpServers:
          filesystem:
            transport: stdio
            command: npx
            args:
              - -y
              - "@modelcontextprotocol/server-filesystem"
              - /path/to/folder
            env:
              API_TOKEN:
                secret: MY_MCP_TOKEN
    ```
  </TabItem>

  <TabItem label="Remote server (HTTP)">
    Connect to a hosted or local HTTP MCP server:

    ```yaml
    agents:
      default:
        mcpServers:
          linear:
            transport: http
            url: https://mcp.example.com/mcp
            headers:
              Authorization:
                secret: LINEAR_AUTH_HEADER
    ```
  </TabItem>
</Tabs>

You can temporarily disable any server by adding `enabled: false` to its entry.

## Add Markdown skills

A **skill** is a folder containing a `SKILL.md` file (plus any optional reference files or scripts). Wheatley tells your assistant which skills are available and lets it read a skill on demand whenever a task matches.

Put skill folders in either location:

- **Shared across all assistants**: `~/.wheatley/skills/<skill-name>/SKILL.md`
- **Only for one assistant**: `~/.wheatley/agents/<agent-name>/skills/<skill-name>/SKILL.md`

To turn off specific skills for one assistant without deleting the files:

```yaml
agents:
  default:
    skills:
      disabled:
        - draft-release-notes
```

## Write a custom plugin

If you want to build your own tools or a custom chat frontend in TypeScript, use `@wheatley-ai/sdk`.

<Steps>

1. **Create an ESM package and install the SDK**

   ```bash
   npm install @wheatley-ai/sdk
   ```

2. **Export your plugin as the default export**

   ```ts
   import { definePlugin } from "@wheatley-ai/sdk";

   export default definePlugin({
     apiVersion: 1,
     name: "hello",
     version: "1.0.0",
     setup: () => ({
       tools: [
         {
           name: "greet",
           description: "Greets the user",
           inputSchema: { type: "object", properties: {} },
           execute: async () => ({
             content: [{ type: "text", text: "Hello" }],
           }),
         },
       ],
     }),
   });
   ```

3. **Install the plugin into Wheatley's extensions folder**

   ```bash
   npm install --prefix ~/.wheatley/extensions <plugin-package>
   ```

4. **Enable the plugin in `config.yaml` and restart your assistant**

   ```yaml
   agents:
     default:
       plugins:
         - source: <plugin-package>
   ```

</Steps>

`source` also accepts a local folder path. Paths starting with `./` or `../` resolve relative to `~/.wheatley`, and paths starting with `~/` resolve relative to your home directory.

Your assistant sees plugin tools as `<plugin>:<tool>` (for example `hello:greet`). Like MCP tools, plugin tools ask for your approval by default.
