Wheatley splits its configuration into two files inside your home folder (`~/.wheatley` by default):

- **`config.yaml`**: Settings for providers, assistants, chat apps, permissions, and extensions. Safe to back up or version-control because it never contains raw keys.
- **`secrets.yaml`**: API keys and bot tokens, stored with owner-only file permissions (`0600`).

Inside `config.yaml`, secrets are always referenced by name (`{ secret: "ANTHROPIC_API_KEY" }`). If an environment variable with the same name is set, it overrides `secrets.yaml`.

<Aside type="note">
  After editing `config.yaml`, restart the changed assistant (or restart the daemon if you changed `daemon` or `webhooks`).
</Aside>

## Full example `config.yaml`

```yaml
version: 1

daemon:
  host: 127.0.0.1
  port: 7420
  drainTimeout: 30s
  allowedOrigins:
    - http://localhost:5173

webhooks:
  enabled: false
  host: 127.0.0.1
  port: 8788

providers:
  anthropic:
    apiKey:
      secret: ANTHROPIC_API_KEY
    maxConcurrent: 4

agents:
  default:
    instructions: Keep replies concise and helpful.
    approvalTimeout: 15m
    model:
      provider: anthropic
      id: claude-sonnet-5-5
      thinking: medium
    permissionPolicy:
      - tool: read_file
        action: allow
      - tool: shell
        action: ask
```

## Controlling what your assistant can do (`permissionPolicy`)

Every assistant has a `permissionPolicy` list that decides which tools run automatically (`allow`), ask you first (`ask`), or are blocked (`deny`).

Rules are checked from top to bottom, and the **first match wins**. Use `*` as a wildcard (for example `mcp:filesystem:*`).

```yaml
agents:
  default:
    permissionPolicy:
      - tool: read_file
        action: allow
      - tool: shell
        action: deny
      - tool: "mcp:filesystem:*"
        action: ask
```

### Default actions when no rule matches

| Tool | Default behavior |
| --- | --- |
| `read_file` | `allow` (runs inside `agents/<name>/workspace`) |
| `write_file`, `shell` | `ask` (runs inside `agents/<name>/workspace`) |
| `memory_search`, `memory_read`, `memory_write`, `memory_delete` | `allow` |
| `schedule_trigger`, `list_triggers`, `cancel_trigger` | `allow` |
| Plugin tools (`<plugin>:<tool>`) | `ask` |
| MCP server tools (`mcp:<server>:<tool>`) | `ask` |

### Approval timeout

When your assistant asks for permission to run a tool, it waits **15 minutes** (`15m`) by default before timing out. Set `approvalTimeout` on an assistant to change that window (for example `30m`), or set `approvalTimeout: null` to wait indefinitely.

## Network listeners

When `wheatley daemon` runs, it listens on two local endpoints:

- **Unix socket** (`~/.wheatley/daemon.sock`): Used automatically by CLI commands on the same machine.
- **Local HTTP/WebSocket listener** (`127.0.0.1:7420`): Serves the web dashboard on `/` and the JSON-RPC WebSocket API on `/ws`.

You can override the TCP address in `config.yaml` (`daemon.host` and `daemon.port`) or on the command line (`wheatley daemon --host ... --port ...`). To point the CLI at a TCP address instead of the Unix socket, pass `--url ws://127.0.0.1:7420/ws`.
