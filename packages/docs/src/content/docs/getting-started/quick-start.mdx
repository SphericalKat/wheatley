In a few minutes, you will have Wheatley running locally with both a terminal chat and a web dashboard.

<Steps>
  1. **Create your Wheatley home folder**

     Run `wheatley init`. By default, Wheatley stores its config and data in `~/.wheatley` (or `$WHEATLEY_HOME` if you set that environment variable):

     ```bash
     wheatley init
     ```

     Want to start with a different provider right away? Pass `--provider` and `--model`:

     ```bash
     wheatley init --provider openai --model gpt-5.4-mini
     ```

2.  **Add your API key**

    Open `~/.wheatley/secrets.yaml` and add the key for your chosen provider. For the default Anthropic setup:

    ```yaml
    ANTHROPIC_API_KEY: sk-ant-...
    ```

    You can also set `ANTHROPIC_API_KEY` as a regular environment variable. Environment variables always override `secrets.yaml`.

3.  **Start Wheatley**

    Start the background daemon in your terminal so you can see its logs while testing:

    ```bash
    wheatley daemon
    ```

4.  **Check that everything is healthy**

    Open a second terminal and run:

    ```bash
    wheatley status
    ```

    You will see your assistant listed as healthy and ready.

5.  **Send your first message**

    Ask a one-off question right from the shell:

    ```bash
    wheatley ask "What can you help me with?"
    ```

    Or open the full interactive terminal chat:

    ```bash
    wheatley chat
    ```

6.  **Open the web dashboard**

         While `wheatley daemon` is running, visit `http://127.0.0.1:7420/` in your browser to chat, review tool approvals, inspect memory, manage secrets, and edit config visually.

    </Steps>

## What `wheatley init` creates

`wheatley init` never overwrites an existing `config.yaml`. On a fresh setup, it creates:

- `~/.wheatley/config.yaml`: Your main settings (models, assistants, chat apps, permissions, and extensions).
- `~/.wheatley/secrets.yaml`: API keys and bot tokens, protected with owner-only file permissions (`0600`).
- `~/.wheatley/agents/default/`: The private workspace, memory, and SQLite database for your first assistant.

### Useful `wheatley init` options

| Flag | Default | What it sets |
| --- | --- | --- |
| `--home <dir>` | `~/.wheatley` | Where to store Wheatley's files |
| `--agent <name>` | `default` | Name of your first assistant |
| `--provider <name>` | `anthropic` | AI provider (`anthropic`, `openai`, `google`, and more) |
| `--model <id>` | `claude-sonnet-5-5` | Model ID to use |

:::note If you start the daemon before adding an API key, Wheatley still starts, but marks your assistant as `degraded`. Run `wheatley status` to see which secret is missing. :::

## Keep Wheatley running in the background

Once you are happy with your setup, stop the foreground daemon (`Ctrl+C`) and install it as a background service so it starts automatically on login:

```bash
wheatley service install
wheatley service start
```

See [Day-to-day operations](/wheatley/reference/operations/) for stopping, restarting, updating, and backing up your service.
